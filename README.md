# Каталог за вечер

Полный исходный код версии 0.4.0 для передачи разработчику. В комплекте бежевое стеклянное оформление, вход и регистрация, кабинет администратора, баланс тестовых токенов, загрузка фото и характеристик, выбор страниц, пожелания, генерация целой карточки, история и экспорт, а также обязательная модерация фото и готового результата.

## Быстрый запуск на Windows

1. Установите Node.js 24.x для Windows x64, если его ещё нет.
2. Распакуйте всю папку `catalog-studio` в обычную папку на компьютере.
3. Запустите `start-local.bat`. Он создаст `.env` из `.env.example` и откроет его для настройки.
4. Укажите `ADMIN_EMAIL` и придумайте `ADMIN_PASSWORD` длиной не менее 10 символов. Чтобы работала генерация, укажите собственный `AI_API_KEY` провайдера ApiMira. Сохраните `.env` и закройте Блокнот.
5. При первом запуске установятся зависимости через npm. Для этого нужен интернет. Дождитесь строки о запуске сервера; окно сервера оставьте открытым.
6. Откройте http://127.0.0.1:3000/ в браузере. Для администратора используйте почту и пароль из `.env`.

Для просмотра интерфейса API-ключ не обязателен. Без него создать изображения нельзя. Не открывайте `index.html` двойным щелчком: регистрация, баланс и генерация требуют работающего сервера.

## Запуск из терминала

В папке проекта:

```powershell
Copy-Item .env.example .env
notepad .env
npm install
npm start
```

Если `.env` уже настроен, не копируйте пример поверх него. После изменения `.env` перезапустите сервер.

## Настройки

- `AI_API_BASE_URL=https://apimira.com/v1` — адрес подключённого провайдера.
- `AI_API_KEY` — собственный серверный ключ. Не размещайте его в браузерном коде и не передавайте вместе с исходниками.
- `AI_IMAGE_MODEL=openai/gpt-image-2.5-sunburst` — генератор изображений.
- `AI_MODERATION_MODEL=openai/gpt-5.4-mini` — проверка изображений и запросов.
- `ADMIN_EMAIL`, `ADMIN_PASSWORD` — создание администратора при первом старте.
- `HOST=127.0.0.1`, `PORT=3000` — локальный адрес сервера.
- `DEMO_PAYMENTS=true` — тестовое начисление токенов. Настоящего приёма платежей пока нет.
- `ACCESS_EMAILS` — список допущенных email через запятую. Непустой список закрывает регистрацию; перечисленные аккаунты нужно предварительно создать. Если нужен только администратор, укажите его email из `ADMIN_EMAIL`.
- `REGISTRATION_OPEN=false` — закрытие регистрации, даже если список `ACCESS_EMAILS` пуст.

Тестовые токены сайта не делают API бесплатным. Генерация и две проверки оплачиваются по тарифам провайдера. Цена 10 ₽ за карточку в интерфейсе — установленный тариф сервиса, а не обещание себестоимости API.

## Проверки безопасности

Модератор получает фото и весь запрос перед генерацией, а затем проверяет готовое изображение перед сохранением. Только ALLOW разрешает продолжение. REJECT, REVIEW, ошибки сети и неправильный JSON останавливают обработку. При отказе на выходе токен сайта возвращается, но затраты провайдера уже могли возникнуть.

Правила хранятся в `product-moderation-policy.txt`. Они основаны на предоставленном документе с исключением отдельного запрета LGBT_THEME: сама тематика или личные характеристики не служат причиной отказа. Ограничения на сексуальный контент, насилие и ненависть применяются одинаково. Классификация моделью может ошибаться; для проверки качества нужны разрешённые, запрещённые и спорные тестовые примеры.

Модуль проверяет JSON на сервере. Его решение нельзя заменить решением из браузера. Фото, ключи и свободные тексты доказательств не записываются в журнал `moderation_checks`.

## Данные

При запуске создаётся новая локальная база `.data/catalog.sqlite3`; изображения сохраняются в `.data/images`. Скопируйте всю `.data` в резервное место перед обновлением работающего экземпляра.

Этот архив содержит чистый проект: в нём НЕТ действующего `.env`, API-ключей, паролей, существующих аккаунтов, балансов, пользовательских фото, базы данных, SSH-ключей и настроек чужого компьютера. Администратор и данные нового экземпляра будут отдельными. Сайт на другом компьютере и доступ к нему этот архив не изменяет.

Выдача изображений требует одобрения текущей версией правил. Если отдельно переносить старую базу, карточки, созданные до обязательной модерации, потребуется пересоздать.

## Проверки кода

После `npm install`:

```powershell
npm test
```

Проверяются вход, права, кошельки, модерация, возврат токенов, передача фото и пожеланий, сохранение и скачивание изображений. Автоматические тесты используют отдельную временную базу и тестовый API; платные генерации и проверки не запускаются.

## Состав

- `server.mjs` — HTTP API, SQLite, аккаунты, баланс и выдача файлов.
- `image-generation.mjs` — запросы создания карточек.
- `product-moderation.mjs` и `product-moderation-policy.txt` — проверки до и после генерации.
- `app.js`, `index.html`, `style.css` — интерфейс.
- `studio-hero.png` — изображение оформления; исходный промпт в `studio-hero-prompt.txt`.
- `package.json` — зависимости и команды.
- `.env.example` — пустой шаблон настроек.
- `start-local.bat` — запуск на Windows.
- `*-tests.mjs`, `auth-smoke.mjs`, `custom-prompt-ui.mjs` — проверки.
- `SHA256SUMS.txt` — контрольные суммы переданных файлов.

`node_modules` в архив не входит: зависимости устанавливаются командой `npm install`. Активный сайт сейчас находится в тестовом режиме. Для публичного запуска отдельно нужны оплата, подтверждение почты и восстановление пароля, HTTPS, резервные копии и необходимые документы сервиса.


## Развертывание и тестовое пополнение на Render

В production-режиме (NODE_ENV=production) обычное демо-пополнение отключено в целях безопасности.

Для административного тестирования баланса на хостинге Render добавлен флаг ADMIN_TEST_TOPUP=true:
- При ADMIN_TEST_TOPUP=true пополнять свой тестовый кошелёк может только аккаунт с ролью **admin**.
- Обычные пользователи и посетители без входа не могут начислять тестовые токены.
- Настоящая оплата не проводится; генерация и модерация расходуют баланс провайдера AI.
- В 
ender.yaml и панели Render задаются:
  `env
  NODE_ENV=production
  ADMIN_TEST_TOPUP=true
  `
- В ответе /api/health будет передаваться dminTestTopup: true.


## Исправления надёжности 0.4.1

Модерация остаётся обязательной до генерации и перед сохранением результата. Примеры ALLOW, REJECT и REVIEW теперь соответствуют серверной схеме с отдельными записями для фото и текста. Пустые необязательные пожелания и служебные коды страниц не считаются сами по себе посторонним заданием. Это уточнение не разрешает запрещённые товары.

При отказе интерфейс сохраняет сообщение, этап проверки и код обращения. Администратор видит последние 30 решений в разделе «Журнал проверок карточек» и через защищённый GET /api/admin/moderation. Обычные пользователи не имеют доступа к этому журналу. Сохраняются короткие основания и наблюдаемые признаки, очищенные от распространённых форматов контактов и секретов; для категории FRAUD_PRIVACY свободные пояснения заменяются общей формулировкой. Сырые фото и промпты в журнал не записываются.

Версия политики считается после нормализации переводов строк. Две явно перечисленные версии прежней политики LF/CRLF совместимы с уточнённым форматом, поскольку их ограничения совпадают. Пустые и неизвестные версии разрешением не считаются. При содержательном изменении ограничений совместимость нужно пересмотреть явно.

HTTP-обработчик игнорирует повреждённые cookie, принимает JSON через единое UTF-8 декодирование и считает лимит в байтах. Ошибки отдельных запросов перехватываются без вывода секретов. Регрессионные тесты проверяют кириллицу и emoji на границах буферов, права на журнал, возвраты токенов, сохранение доступа к ранее одобренным карточкам и работу сервера после некорректных запросов.

Хранение на Render Free в этой версии не изменено по решению владельца: локальные .data и изображения всё ещё могут потеряться при redeploy, restart или засыпании сервиса. Перед установкой обновления сохраните текущие данные. Постоянное хранилище и перенос существующей базы — отдельный следующий этап, платный диск автоматически не подключается.

Автоматические проверки используют тестовый API, а не оценивают истинность решений реальной модели. Для конкретного спорного товара сравните новую запись журнала с исходным фото и запросом.
